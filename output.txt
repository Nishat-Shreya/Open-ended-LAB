===== Computational Complexity Analysis =====
V = vertices, E = edges, R = requests, N = total vehicles,
K = candidate paths per request, L = average edges in a path

Graph generation              : O(V + E) expected
Dijkstra (one run)            : O((V + E) log V)
Candidate path generation     : O(R * K * (V + E) log V)
Assignment: Shortest-Path     : O(N * L)
Assignment: Greedy-LB         : O(N * K * L)
Assignment: Proposed (GMLR)   : O(N * K * L)
Evaluation                    : O(E)
Overall per time step         : O(R*K*(V+E) log V + N*K*L + E)
Memory                        : O(V + E + R*K*L)

Scalability: running time grows almost linearly with N, R and K,
and the Dijkstra part grows with (V+E) log V for bigger graphs.

===== Limitations =====
1) Proposed algorithm (GMLR) is a greedy HEURISTIC, not guaranteed optimal.
   It does not directly minimize global variance or maximum load.
2) Up to K alternative paths are generated using an edge-penalty technique.
   They are NOT guaranteed to be the exact K-shortest simple paths,
   and fewer than K distinct paths may be found.
3) Greedy-LB looks only at the current maximum load, not average or variance.
4) Each time step is treated as an independent scenario (CARRY_LOAD = false).
